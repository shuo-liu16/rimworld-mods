# Auto Clean（自动清扫）

每天到点，自动把居住区里的污渍清干净。不需要小人跑过去，也不消耗资源。

## 用法

`选项 → Mod 设置 → 自动清扫`：

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用每日自动清扫 | 开 | 总开关 |
| 每天清扫时刻 | 06:00 | 按地图本地时间，±1 小时调整，0–23 循环 |
| 只清扫居住区 | 开 | 关闭则清扫全图（矿区、野外也会被清） |
| 清扫后弹出提示 | 开 | 关闭则静默 |
| 立即清扫一次 | — | 测试用，不用等到 6 点 |

## 实现要点

**钩子挂在哪**：`Harmony` postfix 挂在 `TickManager.DoSingleTick()` 上，而不是某个建筑或地图组件上。
理由很实际——游戏暂停时不 tick，快进时 tick 次数跟着变，挂在主循环上才能保证「每天一次」的语义和游戏内时间一致；挂在建筑上则会被拆除、断电、地图切换影响。这也是为什么它依赖 Harmony（`brrainz.harmony`），`About.xml` 里已经声明了这个依赖。

**怎么保证一天只清一次**：每个地图记一个「上次清扫的游戏刻」，`GenTicks.TicksAbs` 差值不足 0.95 天（57000 tick）就跳过。用 0.95 而不是 1.0，是为了在时刻判断落在整点边界上时不至于错过一整天。读到时间更早的存档时差值为负，按「没清过」处理，否则会永久跳过。

**性能上做了三层收窄**：

1. **每 tick 只做一次位与**。钩子挂在 `TickManager.DoSingleTick`（1 倍速 60 次/秒，4 倍速更多），进来先 `(TicksGame & 0xFF) != 0` 早退——每 256 tick（约 4 秒）才真正检查。游戏内一小时是 2500 tick，这个粒度绝不会漏掉整点窗口，也不会出现「刚好错过 6:00」。
2. **分批清扫**。一次性删掉上千个污渍，每个 `Destroy` 都会脏化地块、触发寻路重算，同一帧删完会明显卡一下。所以改成先入队，每次检查只处理 300 个，1000 个污渍约 15 秒清完，分摊到多帧。
3. **不做无谓的遍历**。不在 `Tick` 里扫污渍，只有时间到点才调一次 `ThingsInGroup(Filth)`；队列空了就从字典里移除对应条目。

稳态开销：每秒约 4 次 `HourOfDay` 比较，其余时间只有一次位运算。

**怎么判定污渍**：`map.listerThings.ThingsInGroup(ThingRequestGroup.Filth)` 拿到所有污渍实体（血迹、泥、动物粪、碎石堆都算），再用 `map.areaManager.Home[cell]` 判定是否在居住区内，命中就 `Destroy(DestroyMode.Vanish)`——这是「直接消失」，不会留下掉落物。

**为什么先复制一份列表再删**：`ThingsInGroup` 返回的是游戏内部的实时列表，边遍历边 `Destroy` 会改集合，轻则漏删，重则抛 `InvalidOperationException` 卡进 tick 循环。`Snapshot` 那一行不是多余的。

**异常全部吞掉**：postfix 里 `try/catch` 到 `Log.ErrorOnce`。tick 补丁里抛异常会污染整个游戏主循环，最坏情况是卡死；这里宁可这条功能失效，也不能让存档进不去。

## 健壮性与日志

这个 Mod 挂在游戏主循环上，所以「出错不能影响游戏」比功能本身更重要。

| 边界 | 兜住之后的后果 |
|---|---|
| Harmony 主循环钩子 | 异常被吃掉，只记日志；游戏的 tick 链完全不受影响 |
| 排程检查（逐地图） | 一张地图失败，其它殖民地当天照常清扫 |
| 销毁单个污渍 | 该污渍跳过，整批继续 |
| 设置页绘制 | 设置页显示一行错误提示，选项界面其余部分正常 |
| `PatchAll` 本身 | Mod 仍加载、设置页可用，只是自动清扫不生效 |

日志标签（`Player.log` 里搜 `AutoClean`）：

- `[AutoClean] 已加载，每日自动清扫补丁挂接成功。` —— 正常，说明 Harmony 补丁进去了。
- `[AutoClean] 主循环钩子 出错` —— tick 里的异常（最常见），会附堆栈。
- `[AutoClean] 排程检查 出错` / `销毁污渍 出错` / `立即清扫 出错` —— 定位到具体阶段。
- `[AutoClean] Harmony 补丁 出错` —— 补丁没打上，自动清扫不会工作，但游戏正常。

同一位置最多输出 3 条，之后静默，避免高频路径刷屏。

## 已知限制

- 是「魔法清扫」，没有小人动画、没有工作量、不消耗电力。想要「需要清洁工真的去扫」的版本，得走 JobDriver，工作量大一个数量级。
- 只删污渍实体，不处理「污渍将生成」的中间状态（比如刚踩出来的还没落地）。
- 同一时刻多个地图都有殖民地时会各自清扫一次，各自独立计时。
- 如果装了别的 Mod 也去改 `Filth` 的销毁逻辑，可能互相抢——但目前没有已知冲突。

```bash
python ../../../tools/gen-assets.py . net10.0
"C:\Users\Shuo-\.dotnet\dotnet.exe" build --no-restore
# 产物：../../Assemblies/AutoClean.dll
```

引用 `Assembly-CSharp.dll`、`Waylith.dll`、`UnityStubs.dll` 以及 Harmony 的 `0Harmony.dll`（全部 `Private=false`）。

## 排错

| 现象 | 原因 |
|---|---|
| Mod 设置里没有「自动清扫」 | DLL 没进 `Assemblies/`，或 About.xml 的 packageId 与文件夹冲突 |
| 到点没清扫 | 检查总开关；确认地图时间确实走到了设定时刻；看是否 `只清扫居住区` 而污渍在区外；或者**根本没画居住区**（没画就没有 Home 区域，等于一个都不清） |
| 日志有 `HarmonyException` | Harmony 版本太旧。1.7 需要 Harmony 3.x，订阅创意工坊最新版即可 |
| 日志有 `[AutoClean] tick 出错` | 会带堆栈，把它发出来 |
