# Work Sorter（工作优先级排序）

给 RimWorld 1.7 加一个底栏标签页：**按「谁擅长什么 × 基地现在缺什么」自动排出 1-4 档工作优先级**。

写这个 Mod 的原因很具体：殖民地一过十个人，工作页就变成一张要手工填的表。二十多个工作 × 十几个人，每次招新人、每次有人受伤、每次基地从「造房子」转成「种地」，都得把整张表重排一遍。原版只给了 `naturalPriority` 这个固定的列顺序，帮不上忙。

---

## 功能

### 一张表看完所有人和所有工作

底栏「排班」（在「工作」左边），点开就是 `工作 × 殖民者` 的矩阵：

- 格子里的数字是**建议的优先级**（1 最高 / 4 最低）
- 绿色 = 第一档，往下依次黄、橙、暗红
- **细框** = 这一格和现在的游戏内数值不同，应用后会变
- **蓝粗框** = 已锁定，自动排序不会碰
- 鼠标悬停任意格子，会列出这一分的完整构成（技能、热情、速度、能力、需求）

确认无误后点「应用全部」写回游戏；也可以直接点某一格——立刻生效并顺手锁定它。

### 评分模型

每个人对每项工作算一个适配度 `fit`，只读不写：

| 因子 | 权重 | 怎么来的 |
|---|---|---|
| 技能 | 0.40 | `WorkTypeDef.relevantSkills` 的加权平均等级（有热情的技能权重更高），18 级封顶 |
| 热情 | 0.18 | 无 / 有兴趣 / 狂热（有火）→ 0 / 0.5 / 1 |
| 工作速度 | 0.20 | 该工作的**专属速度属性**（施工、采矿、研究、种植各有各的）与 `WorkSpeedGlobal` 的几何平均 |
| 身体能力 | 0.15 | 按工作标签挑真正用得到的能力取最小值：手上活看 Manipulation，搬运看 Moving，狩猎看 Sight |
| 职业背景 | +0.25 | 童年/成年背景里对应技能的加成，避免「20 级厨师被算成和矿工一样会挖矿」 |

工作速度这一项是刻意加的：技能等级只说明「学得多」，不能反映仿生腿、基因、受伤、疾病。一个 12 级建造但有两条仿生手的工人，实际就是比 15 级没手的快。

### 需求侧：基地现在缺什么

优先级不能只看人，还得看活。需求分三块相加：

```
需求 = 原版 naturalPriority / 1400        （0.07 ~ 1.0）
     + 地图积压量                          （0 ~ 0.55）
     + 稀缺度（能做这活的人越少越高）        （0 ~ 0.25）
```

原版每个 `WorkTypeDef` 都带 `naturalPriority`（消防 1400、医生 1300、研究 100…），这本来就是设计者给的工作重要度排序，直接拿来当基线，顺带自动支持其它 Mod 新增的工作类型。

积压量只读现成的列表长度，不做全图遍历：

| 工作 | 指标 |
|---|---|
| 搬运 | `listerHaulables.ThingsPotentiallyNeedingHauling().Count` |
| 建造 | 蓝图 + 框架 + 拆除/卸载标记 |
| 采矿 | `Mine` / `MineVein` 标记数 |
| 种植/砍伐 | `CutPlant` / `HarvestPlant` 标记 + 成熟作物 |
| 清洁 | `ThingRequestGroup.Filth` 数量 |
| 医疗 | 自己人里倒地或需要包扎的人数 |
| 研究 | 有进行中的项目时把基线抬到 0.45 |

用对数压缩后再归一：30 件待搬和 300 件待搬不该差十倍。

### 两阶段分配

只按分数排序会出两个问题：所有人都把做饭排第一（没人搬砖），或者最全能的人把所有活都占成第一档。所以分两步：

1. **岗位分配**——工作按需求从高到低，给每项挑出最合适的 1-3 个人排第一档。关键岗位（医生、看守、驯养）固定配 2 人，防止主负责人倒下就没人接班。每人最多占 3 个「1」，可在设置里改。
2. **个人排序**——剩下的工作按各人的适配度排成 2/3/4 档：前 40% 给 2，接着 40% 给 3，最后 20% 给 4。完全不适配（适配度 < 0.16）直接扔 4。

消防、就医、卧床这三项是原版 `alwaysStartActive` 的工作，照原版语义全员第一档，且不占那三个名额。

需求不够高的冷门工作（艺术这种）**不设第一档**——没人排 1，大家顺手的时候做。否则总会硬拉一个人专门去雕石头。

### 锁定

- 点任意格子 = 应用并锁定；再点一次解锁
- 点表头的人名 = 锁定整人，自动排序完全跳过它
- 锁定跟着**存档**走（存在 `GameComponent` 里），换殖民地不会继承

### 自动刷新

默认每 1 天（游戏内）重排一次，可在设置里改 1-7 天。

**装好 Mod 之后不会立刻改动你现有的排班**：必须先在面板上按过一次「应用全部」，自动排序才开始按周期接手。否则第二天进游戏，整张表被悄悄换掉，那种体验比手动排还糟。

## 怎么用

1. 底栏点「排班」。
2. 看一遍表。觉得哪一格不对，悬停看看分数构成——如果是「技能低但热情高」导致的，那就是算法本意；如果确实不合适，点一下锁定它。
3. 点「应用全部」。
4. 之后它会每天自己重排。不想自动就点「自动：关」。

### 设置项（选项 → Mod 设置 → 工作优先级排序）

| 项 | 默认 | 说明 |
|---|---|---|
| 启用定时自动排序 | 开 | 关掉后只能手动 |
| 刷新间隔 | 1 天 | 太频繁会让小人来回换活 |
| 每人第一档上限 | 3 项 | 防止全能选手垄断第一档 |
| 接管未启用的工作 | 关 | 默认不碰你手动关掉（空白）的工作 |
| 应用后弹出提示 | 关 | 关闭时只写日志 |

## 已知限制

- **只排自由民和奴隶**。机械族不参与——它们的工作由机械师控制组管理，按 1-4 排会和那套机制打架。
- **不处理「从没启用」和「玩家手动关闭」的区别**。优先级为空的格子一律不动，除非在设置里打开「接管未启用的工作」。
- **优先级只用 1-4**。如果你装了把范围扩到 1-9 的 Mod（PriorityMaster 之类），本 Mod 仍只写 1-4，等于全部挤在上半区。加载顺序上它不冲突，但数值语义要自己权衡。
- **不修改工作页 UI**。和 Fluffy's Work Tab、Better Work Tab 这类重画工作页的 Mod 没有硬冲突：本 Mod 只写 `workSettings` 的优先级数字，它们读的也是同一份数据。
- 积压量指标只覆盖原版那几项工作。Mod 新增的工作类型拿不到积压数据，只吃 `naturalPriority` 和稀缺度。

## 技术要点

- 零 Harmony 以外的依赖，且 Harmony 只用来做一件事：在 `Game.FinalizeInit` 之前把 `WorkSorterGameComponent` 塞进 `game.components`。
- 评分全部走原版现成 API：`Pawn.WorkTypeIsDisabled`（特性/背景/意识形态/基因的禁用一次到位）、`Pawn_WorkSettings.SetPriority`、`StatExtension.GetStatValue`、`PawnCapacityDefOf.*`。
- `Pawn_WorkSettings.LowestPriority` 是读的静态字段而不是写死 4，装了扩展优先级范围的 Mod 也不会越界。
- 面板 250 tick 重算一次预览，绘制阶段只读结果；表格按滚动位置裁剪，滚出屏幕的行连 Widget 都不建。
- 锁定用 `HashSet<long>`（`pawnId << 32 | defNameHash`）而不是字符串 key——表格每帧要查几百次，拼字符串会持续制造垃圾。
- 异常边界：面板绘制、自动刷新、单格写入、单个人写入都有 try/catch，出错只记日志，不冒泡进游戏主循环。

日志标签统一为 `[WorkSorter]`，出错信息在 `Player.log` 里搜这个前缀。
