# Work Sorter（工作优先级排序）

给 RimWorld 1.7 加一个底栏标签页：**按「谁擅长什么 × 基地现在缺什么」自动排出 1-4 档工作优先级**。

写这个 Mod 的原因很具体：殖民地一过十个人，工作页就变成一张要手工填的表。二十多个工作 × 十几个人，每次招新人、每次有人受伤、每次基地从「造房子」转成「种地」，都得把整张表重排一遍。原版只给了 `naturalPriority` 这个固定的列顺序，帮不上忙。

---

## 功能

### 一张表看完所有人和所有工作

底栏「排班」（在「工作」左边），点开就是 `工作 × 殖民者` 的矩阵：

- 格子里的数字是**建议的优先级**（1 最高 / 4 最低）
- 绿色 = 第一档，往下依次黄、橙、暗红
- **细框** = 这一格和现在的游戏内数值不同，应用后会变
- **蓝粗框** = 已锁定，自动排序不会碰
- 鼠标悬停任意格子，会列出这一分的完整构成（技能、热情、速度、能力、需求）

确认无误后点「应用全部」写回游戏；也可以直接点某一格——立刻生效并顺手锁定它。

### 评分模型

每个人对每项工作算一个适配度 `fit`，只读不写：

| 因子   | 权重    | 怎么来的                                                      |
| ---- | ----- | --------------------------------------------------------- |
| 技能   | 0.40  | `WorkTypeDef.relevantSkills` 的加权平均等级（有热情的技能权重更高），18 级封顶   |
| 热情   | 0.18  | 无 / 有兴趣 / 狂热（有火）→ 0 / 0.5 / 1                             |
| 工作速度 | 0.20  | 该工作的**专属速度属性**（施工、采矿、研究、种植各有各的）与 `WorkSpeedGlobal` 的几何平均  |
| 身体能力 | 0.15  | 按工作标签挑真正用得到的能力取最小值：手上活看 Manipulation，搬运看 Moving，狩猎看 Sight |
| 职业背景 | +0.25 | 童年/成年背景里对应技能的加成，避免「20 级厨师被算成和矿工一样会挖矿」                     |

工作速度这一项是刻意加的：技能等级只说明「学得多」，不能反映仿生腿、基因、受伤、疾病。一个 12 级建造但有两条仿生手的工人，实际就是比 15 级没手的快。

### 需求侧：基地现在缺什么

优先级不能只看人，还得看活。需求分三块相加：

```
需求 = 原版 naturalPriority / 1400        （0.07 ~ 1.0）
     + 地图积压量                          （0 ~ 0.55）
     + 稀缺度（能做这活的人越少越高）        （0 ~ 0.25）
```

原版每个 `WorkTypeDef` 都带 `naturalPriority`（消防 1400、医生 1300、研究 100…），这本来就是设计者给的工作重要度排序，直接拿来当基线，顺带自动支持其它 Mod 新增的工作类型。

积压量只读现成的列表长度，不做全图遍历：

| 工作    | 指标                                                        |
| ----- | --------------------------------------------------------- |
| 搬运    | `listerHaulables.ThingsPotentiallyNeedingHauling().Count` |
| 建造    | 蓝图 + 框架 + 拆除/卸载标记                                         |
| 采矿    | `Mine` / `MineVein` 标记数                                   |
| 种植/砍伐 | `CutPlant` / `HarvestPlant` 标记 + 成熟作物                     |
| 清洁    | `ThingRequestGroup.Filth` 数量                              |
| 医疗    | 自己人里倒地或需要包扎的人数                                            |
| 研究    | 有进行中的项目时把基线抬到 0.45                                        |

用对数压缩后再归一：30 件待搬和 300 件待搬不该差十倍。

### 两阶段分配

只按分数排序会出两个问题：所有人都把做饭排第一（没人搬砖），或者最全能的人把所有活都占成第一档。所以分两步：

**第一步，岗位分配。** 每项工作按下面这个键排序，从高到低挑人：

```
排序键 = 需求 × 0.55 + 该工作最强候选人的适配度 × 0.45
```

为什么不是纯按需求排：医生、看守、放囚犯这些 `naturalPriority` 极高的岗位会先占满每个人的名额，等排到烹饪、建造时已经没有位置了——结果是厨师去做急救、矿工去拨开关，真正该由专人干的事全掉到第二档。把"有没有人真的擅长"算进去，专业岗才能拿到名额。

挑选时还有几条约束：

- **技能门槛**：有技能要求的工作，第一档只从相关技能 ≥ 3 级的人里挑。一个达标的都没有时，关键岗位（医生、看守、驯养）仍然找人兜底，其它工作干脆不设第一档——等练出人来再说。
- **第二人也要沾边**：关键岗位配 2 人是为了防止主负责人倒下没人接班，不是随便拉个不会医疗的人当"第二医生"。
- **积压过半多派一人**：三十件货堵在仓库门口和只有三件，拿到的人手应该不一样。
- **每人最多 3 个「1」**，可在设置里改。覆盖保证（关键岗位不能没人）允许每人破例一次，但只破一次——否则所有关键岗位会轮流硬塞同一个人。

**第二步，个人排序。** 剩下的工作按各人的适配度排成 2/3/4 档：前 40% 给 2，接着 40% 给 3，最后 20% 给 4。完全不适配（适配度 < 0.16）直接扔 4。

消防、就医、卧床这三项是原版"谁碰上谁做"的工作，全员第一档，且不占那三个名额。`BasicWorker`（放囚犯、拨开关）虽然原版也是默认开启，但它有真实工作量，照常参与竞争——否则每人先白拿一个名额。

需求不够高的冷门工作（艺术这种）**不设第一档**——没人排 1，大家顺手的时候做。否则总会硬拉一个人专门去雕石头。

### 锁定

- 点任意格子 = 应用并锁定；再点一次解锁
- 点表头的人名 = 锁定整人，自动排序完全跳过它
- 锁定跟着**存档**走（存在 `GameComponent` 里），换殖民地不会继承

### 自动刷新

默认每 1 天（游戏内）重排一次，可在设置里改 1-7 天。所有玩家定居点（主基地 + 分基地）都会排，不是只排你当前看的那张图。

**装好 Mod 之后不会立刻改动你现有的排班**：必须先在面板上按过一次「应用全部」，自动排序才开始按周期接手。否则第二天进游戏，整张表被悄悄换掉，那种体验比手动排还糟。

## 怎么用

1. 底栏点「排班」。
2. 看一遍表。觉得哪一格不对，悬停看看分数构成——如果是「技能低但热情高」导致的，那就是算法本意；如果确实不合适，点一下锁定它。
3. 点「应用全部」。
4. 之后它会每天自己重排。不想自动就点「自动：关」。

### 设置项（选项 → Mod 设置 → 工作优先级排序）

| 项        | 默认  | 说明               |
| -------- | --- | ---------------- |
| 启用定时自动排序 | 开   | 关掉后只能手动          |
| 刷新间隔     | 1 天 | 太频繁会让小人来回换活      |
| 每人第一档上限  | 3 项 | 防止全能选手垄断第一档      |
| 接管未启用的工作 | 关   | 默认不碰你手动关掉（空白）的工作 |
| 应用后弹出提示  | 关   | 关闭时只写日志          |

## 已知限制

- **只排自由民和奴隶**。机械族不参与——它们的工作由机械师控制组管理，按 1-4 排会和那套机制打架。
- **面板只显示当前地图**的人。分基地的排班由定时刷新在后台处理，表里看不到。
- **一格活都做不了的人不出现在表里**（婴儿、长期昏迷、被基因锁死全部工作）。他们占一列空白没意义。
- **不处理「从没启用」和「玩家手动关闭」的区别**。优先级为空的格子一律不动，除非在设置里打开「接管未启用的工作」。
- **优先级只用 1-4**。如果你装了把范围扩到 1-9 的 Mod（PriorityMaster 之类），本 Mod 仍只写 1-4，等于全部挤在上半区。加载顺序上它不冲突，但数值语义要自己权衡。
- **不修改工作页 UI**。和 Fluffy's Work Tab、Better Work Tab 这类重画工作页的 Mod 没有硬冲突：本 Mod 只写 `workSettings` 的优先级数字，它们读的也是同一份数据。
- 积压量指标只覆盖原版那几项工作。Mod 新增的工作类型拿不到积压数据，只吃 `naturalPriority` 和稀缺度。

## 和同类 Mod 的区别

同类大致分三档：只改 UI 的、只做自动分配不碰 UI 的、以及把两者都吃下的。本 Mod 在第二档，而且刻意做得很窄。

| Mod | 它主要做什么 | 和本 Mod 的关系 |
|---|---|---|
| Fluffy's Work Tab | 重画工作页：多列、可扩展的优先级范围 | 不排序。与本 Mod 共存，两边读的是同一份 `workSettings` |
| PriorityMaster | 把优先级范围扩到 1-99 | 共存，但本 Mod 只写 1-4，会全部挤在上半区 |
| Better Work Tab | 重画工作页 + 规则化自动分配 | 共存不冲突，但两套自动规则会互相覆盖，别同时开 |
| Work Manager | 按「专职 / 最高技能 + 热情」分配，另有三班倒排班；1.6 起依赖 `LordKuper.Common`，且必须排在 Work Tab 之后 | 功能比本 Mod 全（排班、逐工作类型开关）。本 Mod 不排班，不引共享库 |
| Adaptive Priorities | 按技能、热情、特性、基因、仿生打分，带覆盖保证、机械族与无人机感知、灵感路由；默认对新殖民地开启 Auto | 功能面比本 Mod 宽得多。本 Mod 的差异只在「分数可见」和「先预览再接管」 |
| Automated Work Assignment | 按人数或百分比分配人选，带按技能分段的专家规则；与 Fluffy's Work Tab 不兼容 | 它的规则更细。本 Mod 不做人数配额 |

也就是说：**论功能，本 Mod 是这几个的子集**。真要说不同的地方，只有三条：

1. **分数是白盒的**。鼠标停在任意格子上，会列出技能 / 热情 / 速度 / 能力 / 背景各贡献了多少，以及需求侧的具体数字（「待搬运物品 43 → 0.82」）。判断对不对可以当场验证，不用猜。
2. **默认不动你的排班**。装好之后必须先手动按一次「应用全部」，定时重排才会接管。上面几个多数是装完即生效。
3. **零 UI 侵入、零共享库**。不开新工作页、不重画原版页，只往 `workSettings` 写数字，所以和 Work Tab 那一系不需要排加载顺序。

明确不做的事：不做「学习你手动操作的历史」（Adaptive Priorities 做了，而且做得比这里好）、不做排班轮班、不排机械族、不做逐工作类型的精细规则、不重画 UI。

如果你要的是功能最全的那一个，上面几个更合适。这个 Mod 的定位是**最容易被看懂、也最不容易惹麻烦的那一个**。

## 技术要点

- 零 Harmony 以外的依赖，且 Harmony 只用来做一件事：在 `Game.FinalizeInit` 之前把 `WorkSorterGameComponent` 塞进 `game.components`。
- 评分全部走原版现成 API：`Pawn.WorkTypeIsDisabled`（特性/背景/意识形态/基因的禁用一次到位）、`Pawn_WorkSettings.SetPriority`、`StatExtension.GetStatValue`、`PawnCapacityDefOf.*`。
- `Pawn_WorkSettings.LowestPriority` 是读的静态字段而不是写死 4，装了扩展优先级范围的 Mod 也不会越界；读到 0（静态构造没跑）时退回 4，否则所有格子会被 clamp 成 0，等于「这个人什么都不做」。
- 面板 250 tick 重算一次预览，绘制阶段只读结果；表格按滚动位置裁剪，滚出屏幕的行连 Widget 都不建。存档组件一帧只取一次——`Game.GetComponent<T>()` 内部是遍历 components 列表，按格子各取一次就是每秒上万次遍历。
- 需求侧（含唯一的全图遍历「伤员统计」）按 25 秒缓存，点「重新计算」会主动失效。缓存跟着 `Game` 引用和 `map.uniqueID` 走，读档后不会命中上一局的旧数据。
- 锁定用 `HashSet<long>`（`pawnId << 32 | defNameHash`）而不是字符串 key——表格每帧要查几百次，拼字符串会持续制造垃圾。
- 分配里的所有排序都带确定的 tie-breaker。`List.Sort` 不稳定，同分项按任意顺序进场会让每次重算产出不同的排班，玩家会看到优先级每隔几秒自己跳。
- 异常边界：面板绘制、自动刷新、单格写入、单个人写入都有 try/catch，出错只记日志，不冒泡进游戏主循环。
- `tools/work-sorter-algo-check.py` 是分配逻辑的离线回归脚本（复刻，不是直接调用），改了权重或排序键要同步改它。

日志标签统一为 `[WorkSorter]`，出错信息在 `Player.log` 里搜这个前缀。
