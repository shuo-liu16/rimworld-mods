# 创意工坊文案（可直接粘贴）

> 用法：在游戏内「选项 → Mod 设置 → 选中 Mod → 上传到 Steam 创意工坊」时，
> **标题**填到 Title，**简介**填到 Description 开头（前两行会显示在工坊列表里），
> **正文**整段粘在简介后面。纯文本，不要用 Markdown 语法（工坊不渲染）。

## 电网与温控 / Grid & Thermal Console

**标题**

```
电网与温控 | Grid & Thermal Console
```

**简介（工坊列表里显示的那两行）**

```
底栏新增「电网」页：一表看全所有电网的发电、耗电、储能与状态；加热器与制冷器可分组统一控温，季节模式会自动给反季设备断电。
```

**正文**

```
【1. 介绍】

给底栏加一个「电网」标签页（排在「建筑师」右边），做两件事：

· 把全图每一张独立电网列成一张表，谁在发电、谁在耗电、谁快撑不住了，一眼看完。
· 把加热器和制冷器分成组，一组共用一个目标温度，点一下就能整组调整。

需要 RimWorld 1.7。不依赖 Harmony，不改任何原版数值，只改设备自己的「目标温度」和「电源开关」，所以断电、EMP、故障、过热保护这些原版行为全部保留。

【2. 解决的问题】

原版想知道电力够不够用，只能一根一根电线去点，点开还只能看那一个网。基地一铺开，哪条线路快超载就变成了猜谜。

温度这边更琐碎：十几个加热器、制冷器各设各的目标温度，想把整个基地压到 21 度得挨个点，漏掉一台就是某个房间过冷或过热；而一台空调和一台暖气设成同一个温度时，它们会因为读到零点几度的差异互相抵消，白烧电。

【3. 如何使用】

一、看电力

点底栏「电网」→「电力网络」页。每张电网一行：发电 / 耗电 / 净输出 / 储能（当前·容量）/ 电量百分比 / 状态（正常·放电中·缺电），最上面一行是全图汇总。

二、建温控组

选中任意一台加热器或制冷器 → 点 gizmo 栏里的「温控分组：未分组」→ 选已有分组或新建分组（自动命名「温控组 1」「温控组 2」…）。

三、调温

回到「电网」→「温控分组」页，每组一行：
· 「模式」按钮切换 统一 / 季节
· 温度按钮是 [-5][-1] 数值 [+1][+5]，冷季那一列同理（只在季节模式出现）
· 「选中」一次选中组内全部设备，「解散」清除分组

四、两种模式怎么选

统一：所有设备同一个目标温度。适合冷库、单间。
季节：热季只开制冷、冷季只开制热，反季那一类设备直接断电——不是把目标设成极端值，待机功耗也省了。

季节判定用的是地图的季节平均温度，不是瞬时室外温度，所以不会一天之内反复切换。

典型配置：
· 冷库 → 单独一组，「统一」，-5°C
· 生活区（省心）→ 空调 + 暖气同组，「统一」，21°C
· 生活区（省电）→ 「季节」，热季 24°C、冷季 20°C

五、能用在哪

判断标准只有一条：这台设备是不是用原版的 CompTempControl 组件控温。
原版只有加热器和制冷器两个；其它 Mod 的空调、暖气绝大多数也复用这个组件，Mod 启动时会自动识别并挂上分组功能，不需要兼容补丁，日志里会打「已为 N 种温控设备自动挂载分组组件」。

注意：
· 面板显示的室温取的是设备所在格的环境温度，嵌在墙里的制冷器可能读到室外那一侧。
· 类型无法识别的第三方温控设备（既不是原版空调也不是原版暖气），季节模式不会给它断电，只让它跟随目标温度——宁可少控，不猜错方向。
· 你手动用原版按钮改过某台机器的温度，最多 4 秒会被组设定覆盖回去。
· 已有的存档不用重建，老建筑会自动获得分组按钮。

【4. 如何贡献】

· 发现 Bug：优先去 GitHub Issues，能贴日志和截图；也可以在工坊页面留言。
   https://github.com/shuo-liu16/rimworld-mods/issues
· 报 Bug 请附：游戏版本、Mod 列表、复现步骤，以及 Player.log 里搜索 GridThermal 的片段
   （日志路径：%USERPROFILE%\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log）
· 想改代码：欢迎 PR。源码在仓库 mods/GridThermal/Source 下，改完请先跑 build.bat 并确认编译通过，
   因为仓库里提交了编译好的 DLL，PR 里要一起带上。
· 想加新的控温策略、新的电力统计维度，也欢迎在 Issues 里先讨论。

但任何 Mod 组合都存在未知冲突的可能。
```

## 自动清扫 / Auto Clean

**标题**

```
自动清扫 | Auto Clean
```

**简介（工坊列表里显示的那两行）**

```
每天在设定时刻自动清除居住区污渍：不需要小人动手，不消耗资源，分批处理不卡顿。时刻、范围、提示都能在 Mod 设置里改。
```

**正文**

```
【1. 介绍】

每天到点，把居住区里的污渍清干净。不用派清洁工，不用等他们走过去，也不消耗任何资源。

时刻、范围、是否弹提示都可以在设置里改，另有一个「立即清扫一次」按钮，用来验证是否生效。

需要 RimWorld 1.7 和 Harmony。Harmony 在创意工坊订阅最新版即可，本 Mod 已在 About.xml 里声明依赖和加载顺序。

【2. 解决的问题】

基地一忙起来就满地血、泥和动物粪，清洁工永远不够用；不扫，小人的心情和房间美观度就往下掉；手动框选清扫又要点好几次，还得记得。

这个 Mod 把这件事变成"每天自动发生一次"，你不用再管。

【3. 如何使用】

一、设置

选项 → Mod 设置 → 自动清扫：

· 启用每日自动清扫（默认开）：总开关
· 每天清扫时刻（默认 06:00）：按地图本地时间，±1 小时调整，0–23 循环
· 只清扫居住区（默认开）：关闭则清扫全图，矿区和野外也会被清
· 清扫后弹出提示（默认开）：关闭则静默
· 立即清扫一次：测试用，不用等到 6 点

二、会清掉什么

污渍实体：血迹、泥土、动物粪、碎石堆都在内。到点后直接消失，不会留下掉落物。

三、性能

· 主循环里每 256 tick（约 4 秒）才检查一次，其余时间只有一次位运算
· 清扫分批进行，每批 300 处，大扫除后不会因为同一帧删掉上千个实体而卡一下
· 稳态开销约为每秒 4 次时间判断，对帧率的影响低于测量噪声

注意：
· 这是"魔法清扫"，没有小人动画，也不消耗工作量。
· 如果没画居住区，「只清扫居住区」等于一个都不清。
· 多张地图都有殖民地时会各自清扫一次，各自独立计时。
· 只处理已落地的污渍实体，不处理"即将生成"的中间状态。

【4. 如何贡献】

· 发现 Bug：优先去 GitHub Issues，能贴日志和截图；也可以在工坊页面留言。
   https://github.com/shuo-liu16/rimworld-mods/issues
· 报 Bug 请附：游戏版本、Mod 列表、复现步骤，以及 Player.log 里搜索 AutoClean 的片段
   （日志路径：%USERPROFILE%\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log）
· 想改代码：欢迎 PR。源码在仓库 mods/AutoClean/Source 下，改完请先跑 build.bat 并确认编译通过，
   因为仓库里提交了编译好的 DLL，PR 里要一起带上。
· 想让它"需要真的清洁工去扫"，那是另一套实现（走 JobDriver），欢迎在 Issues 里讨论方向。

【5. 免责声明】

个人自制自用，按现状提供（AS IS），不提供任何担保，使用风险自负。
代码以 MIT 协议开源，可自由取用、修改、二次分发，无需署名。
本 Mod 会直接销毁地图上的污渍实体，建议首次使用前备份存档。
```

## 工作优先级排序 / Work Sorter

**标题**

```
工作优先级排序 | Work Sorter
```

**简介（工坊列表里显示的那两行）**

```
底栏新增「排班」页：按技能、热情、实际工作速度和基地待办量，算出每个人每项工作的 1-4 档优先级。表上预览再一键应用，逐格锁定永不被覆盖。
```

**正文**

```
【1. 介绍】

给底栏加一个「排班」标签页（在「工作」左边），是一张 工作 × 殖民者 的矩阵：

· 格子里是建议的优先级数字（1 最高 / 4 最低），按档位上色
· 细框表示"这一格应用后会变"，蓝粗框表示"已锁定"
· 鼠标悬停任意格子，列出这一分的完整构成：技能、热情、速度、能力、需求

确认无误点「应用全部」写回游戏；也可以直接点某一格，立刻生效并顺手锁定。

需要 RimWorld 1.7 和 Harmony。

【2. 解决的问题】

殖民地一过十个人，工作页就变成一张要手工填的表。二十多个工作 × 十几个人，每次招新人、有人受伤、基地从"造房子"转成"种地"，都得把整张表重排一遍。原版只给了固定的列顺序，帮不上忙。

更麻烦的是"该排谁"没有标准：技能高的人不一定有时间，有火的人不一定技能够，某个岗位可能已经有三个人在抢。

【3. 怎么算的】

每个人的适配度看五项：

· 相关技能等级（有热情的技能权重更高，18 级封顶）
· 热情：无 / 有兴趣 / 狂热 → 0 / 0.5 / 1
· 实际工作速度：该工作的专属速度属性（施工、采矿、研究、种植各有各的）与全局工作速度取几何平均——这一步让仿生、基因、伤病都算进来
· 身体能力：按工作标签挑真正用得到的能力取最小值（手上活看操作，搬运看移动，狩猎看视觉）
· 童年/成年职业背景里对应技能的加成

需求侧三块相加：

· 原版 naturalPriority / 1400（消防 1400、医生 1300、研究 100…），本来就是设计者给的重要度排序，还能自动支持其它 Mod 新增的工作类型
· 地图积压量：待搬运物品、蓝图与拆除标记、采矿标记、成熟作物、污渍、伤员，取对数压缩
· 稀缺度：能做这活的人越少，权重越高

分配分两步：先按需求给每项工作挑出最合适的 1-3 人排第一档（医生、看守这类关键岗位固定 2 人，防主负责人倒下没人接班），剩下的工作再按各人适配度排进 2/3/4 档。每人默认最多占 3 个「1」。

消防、就医、卧床照原版语义全员第一档。需求不够高的冷门工作（艺术这种）不设第一档，大家顺手的时候做。

【4. 如何使用】

底栏点「排班」→ 看一遍表 → 觉得哪格不对就点一下锁定 → 点「应用全部」。

之后它每天自动重排一次。注意：装好 Mod 之后不会立刻改你现有的排班，必须先在面板上按过一次「应用全部」，自动排序才开始按周期接手。

设置（选项 → Mod 设置 → 工作优先级排序）：

· 启用定时自动排序（默认开）
· 刷新间隔（默认 1 天，1-7 天可调）
· 每人第一档上限（默认 3 项）
· 接管未启用的工作（默认关：你手动关掉的工作不会被重新打开）
· 应用后弹出提示（默认关）

【5. 已知限制】

· 只排自由民和奴隶。机械族不参与——它们的工作由机械师控制组管理，按 1-4 排会打架。
· 优先级只用 1-4。如果装了把范围扩到 1-9 的 Mod，本 Mod 仍只写 1-4，等于全挤在上半区。
· 不修改工作页 UI。和重画工作页的 Mod（Fluffy's Work Tab、Better Work Tab 等）没有硬冲突：本 Mod 只写优先级数字，它们读的也是同一份数据。
· 积压量指标只覆盖原版那几项工作；Mod 新增的工作类型只吃 naturalPriority 和稀缺度。

【6. 如何贡献】

· 发现 Bug：优先去 GitHub Issues，能贴日志和截图；也可以在工坊页面留言。
   https://github.com/shuo-liu16/rimworld-mods/issues
· 报 Bug 请附：游戏版本、Mod 列表、复现步骤，以及 Player.log 里搜索 WorkSorter 的片段
   （日志路径：%USERPROFILE%\AppData\LocalLow\Ludeon Studios\RimWorld by Ludeon Studios\Player.log）
· 想改代码：欢迎 PR。源码在仓库 mods/WorkSorter/Source 下，改完请先跑 build.bat，因为仓库里提交了编译好的 DLL。
```
